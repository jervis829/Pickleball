# 业务流程设计：学员 → 课程包 → 课程大纲 → 备课 → 执行 → 点评

> 本文回答三个问题：（1）As-Is 为什么别扭；（2）To-Be 该是几条流水线；（3）每一屏的交互与跳转怎么设计，为什么这么设计。

---

## 一、As-Is 的真实问题（不是美观问题，是模型问题）

现行流程只有一句话：**「选学员 + 课次 + 课时 → 生成详细教学计划」**。这条流程缺三样东西：

| 缺什么 | 具体表现 | 后果 |
|---|---|---|
| **缺「买了多少节课」这个实体** | 学员档案里只有 `total / used` 两个数字，没有课程包 | 排课没有边界：第 11 节课从哪来？谁交了钱？教练只能凭记忆 |
| **教案没有归属与状态** | `plans` 表只有 `lesson / date / text`，没有「属于哪名学员的哪一节课、上没上、点评没点评」 | 生成完就断线。想追踪只能去「教学追踪」手工补录，且补录记录与教案不是一条线 |
| **缺一个明确的下一步** | 点完「生成详细教学计划」，右侧出现长文档，页面就停了 | 教练的下一步只能靠自觉。**没有动作的界面等于没有流程** |

你说的「点了生成之后没有一个明显下一步要做的 action」——这是整套系统最贵的一个缺口，因为它让前面所有专业内容都停在了「文档」而不是「记录」。

## 二、To-Be：你的构思基本对，我改了三处

### 2.1 你的构思

```
录入学员 → 登记课程（私教/小班）→ 生成整体课程大纲（10 节）→ 授课前生成当天详细计划
```

这条链路是对的，我把它实现成了主线。但有三个地方会出事，我改了：

**改动 1：课程包必须绑定「买了几节」，而不是只绑定「班型」。**
私教/小班/团课决定的是**分组与场地**，不决定**课次数量**。真正决定大纲长度的是「买了 N 节」。所以我把课程包设计成：`学员 + 班型 + 购买课数 + 频次 + 单次时长 + 起始阶段 + 节奏模式`。班型只是一个字段。

**改动 2：大纲不能「先排满 10 节再说」，必须能解释「为什么这 10 节这样分」。**
如果只是把 10 节平均摊给前 5 个单元，那和现在没区别——U14 那种 9 个技术点的单元照样只分到 2 节。所以大纲由**难度 × 单节剂量**推出，每一节都带一份 `pace` 快照，能回答「这个单元为什么要 3 节」。

**改动 3：必须有「未达标怎么办」。**
教学不是线性播放。学员第 1 节没过「准备姿势定格」这条判据，第 2 节就不该进正手。所以课程包带一个**节奏模式**开关：

- **自适应**（默认）：未达标时把下一节改成同单元 R 补强课。**不新增课时、不改单次时长**，只调整顺序。
- **固定**：课已经卖出去了、不能加课。未达标时不动大纲，只在下一节 ③ 分解练习前 5 分钟复习。

这个开关解决了一个真实的商业冲突：教学上想加课，销售上不能加课。系统不该替馆里做决定，但必须两种都支持。

### 2.2 最终流程（三条入口，一个出口）

```
                    ┌─────────────────────────────┐
   ①登记            │ 学员档案（年龄段/技术/体能） │
                    └──────────────┬──────────────┘
                                   ▼
                    ┌─────────────────────────────┐
   ②排课            │ 课程包：买了 N 节 + 频次     │──→ 自动生成 N 节大纲
                    │ （自适应 / 固定）            │     每节：课号·单元·A/B/R·日期
                    └──────────────┬──────────────┘
                                   ▼
   ┌───────────────────────────────────────────────────┐
   │ 今日   ：今天上哪几节 / 已过期未上 / 待点评        │
   │ 课程包 ：大纲全景，逐节「备课」                    │
   │ 教学追踪：历史记录，逐条「点评」                   │
   └───────────────┬───────────────────────────────────┘
                   ▼  点「备课」
        ┌──────────────────────────┐
   ③备课│ 自动带入：学员/课次/时长  │  右侧 = 教案预览
        │ 读历史评分 + 体测报告     │  顶部与底部都有【执行此计划 →】
        └──────────────┬───────────┘
                       ▼  点「执行此计划」
        ┌──────────────────────────────────────────────┐
   ④执行│ 一个事务：授课记录 + 大纲已授课 + 包已用+1 + 学员已耗+1 │
        └──────────────┬───────────────────────────────┘
                       ▼  跳到「本次课」
        ┌──────────────────────────────────────────────┐
   ⑤点评│ 教案全文 + 【点评本次课】→ 3 要点勾选 + 一句话 + 作业 │
        │ 未达标 → 自动把下一节改成同单元补强课             │
        └──────────────────────────────────────────────┘
```

## 三、逐屏交互与跳转设计

### 3.1 课程包页（新增）

**左栏 = 登记表单，右栏 = 当前课程包的大纲。**

- 学员下拉直接显示「姓名 · 阶段 · 已耗 6/48」，避免选错人。
- 「购买课数」是必填正整数，前端先校验，后端再校验（1–200）。
- 生成后**不跳页**：右栏原地变成大纲表格，第一行高亮为「下一节」。理由：教练刚点完生成，最想看的就是「排出来了没有、怎么排的」，跳页会打断这个确认动作。
- 大纲表列：`# / 课次 / 单元 / 类型 / 日期 / 状态 / 操作`。**操作列只有一件事**：待上课 → 「备课」；待点评 → 「去点评」；已点评 → 「查看」。
- 有未点评课次时，右栏顶部出现警示条：**「2 节课还没点评。点名后不点评，这节课就等于没记录 → 现在点评」**。这是把「点评」从可选变成有摩擦的必做。

### 3.2 备课页（原「计划生成」）

改动要点：

1. **入口改名**：「计划生成」→「备课」。名字决定心智：前者像配置工具，后者像上课前的准备动作。
2. **参数已被预填**：从大纲点进来时，学员、课次、时长、日期、班型、目标全部带好，教练只需要确认。左栏仍是可编辑的（教练有权改课次），但默认值是对的。
3. **自动生成**：进入页面后自动触发一次 `generate()`，右侧直接是教案预览。少一次点击，因为这次点击没有决策价值。
4. **【执行此计划 →】出现在两个位置**：
   - 页面顶部执行条：说明「这是第 4 节 · 第 7 单元 · A 新授」，右侧「执行此计划 →」。
   - 教案预览标题区底部：同样的按钮，因为教练读完教案后眼睛在页面底部。
5. **未生成教案时按钮是 disabled**，避免「点了执行但写不出教案」。
6. **可以取消**：执行条上有「取消」，点了只是清掉上下文，教案还在。不强迫。

### 3.3 执行（一个事务，可重入）

```
POST /enrollments/:id/lessons  { outlineLessonId, planId, date, judge?, rpe? }
  BEGIN IMMEDIATE
    INSERT sessions（review_status = 'pending'）
    UPDATE outline_lessons SET status='taught', session_id=?
    UPDATE enrollments SET used_lessons = used_lessons + 1
    UPDATE students   SET used = MIN(total, used+1)
  COMMIT
```

三个设计决定：

- **必须先有教案**（`plan_id` 外键）。前端在执行前若发现还没保存教案，自动先存一份，再调接口。
- **幂等**：同一 `outlineLessonId` 重复调用返回同一 session，`duplicated=true`。理由：教练在手机上可能连点两次，或网络重试。
- **返回 `nextStep`**：执行完立刻告诉教练「这节课判据是什么、没达标会怎样」。不是让前端自己算。

### 3.4 本次课页（新增）

- 顶部：`学员 · 第 N 课 · 分钟数` + 大纲调整说明（如果上一节触发了补强课，这里会写「已把第 3 节改为第 1 单元补强」）。
- 主体：**完整教案**（与原「详细教案」视图一致，分段动作、口令、判据、安全）。
- 右上：`课程大纲 / 打印 / 点评本次课`。
- 已点评时：按钮变「修改点评」，下方追加点评汇总（3 个要点逐个显示达标/未达标 chip）。
- 为什么把教案放在这一页而不是只放在备课页：教练上课时打开的是「今天这节课」，不是「生成器」。

### 3.5 点评（60 秒能做完）

弹窗字段，按填写顺序排：

1. **3 个可观察判据**（来自课程体系 `kp`），每行一个「达标 / 未达标」下拉。**只有两个选项**，不给「部分」——模糊的中间态会让数据没有意义。
2. **总体判据**：达标 / 部分达标 / 未达标。这个字段决定大纲怎么调。
3. **出勤 / RPE**：复用已有字段。
4. **一句话反馈**：placeholder 就是句式「1 条优点 + 1 条改进点」。
5. **家庭作业 / 下节重点**：直接进学员档案，下节课备课时会显示。

保存后的行为：

- `sessions.review_status = 'done'`，`outline_lessons.status = 'reviewed'`。
- 判据非「达标」且节奏为自适应 → 下一节（下一个 `planned`）改成**同单元 R 补强**，`note` 记录「由第 N 节点评自动调整」。
- 返回 `adjust` 文案，前端 toast 显示「点评已保存 · 下一节已改为补强课」。

### 3.6 今日（新增，替代总览的「近期计划」）

三块，按教练当天会问的顺序：

1. **今天要上的课**（按日期精确匹配，含过期未上，过期标红）。
2. **待点评**（所有 `review_status = pending` 的会话，不限于今天——因为漏点评往往发生在昨天）。
3. **入口**：每行一个「备课」或「点评」，不用再点进详情再找按钮。

数据来源：在线时调 `GET /today?date=`，离线时用 `state.enrollments` 本地算（所以离线也能看今天上哪节）。

## 四、为什么这么设计（原则）

| 原则 | 具体体现 |
|---|---|
| **一个页面只留一个主动作** | 大纲行只有「备课」；本次课只有「点评」；备课页主按钮只有「执行此计划」 |
| **下一步必须可见** | 生成教案后立刻出现执行按钮；执行完立刻跳到本次课并提示「记得点评」；点评完立刻说「下一节已改为补强」 |
| **不替教练做决定，但把后果说清楚** | 未达标要不要加课由 `paceMode` 决定，系统只负责算出代价 |
| **动作要么全成要么全不成** | 执行 = 一个事务；重复点不会多扣课时 |
| **离线不装在线** | 课程包需要落库，离线时明确提示，不假装成功 |
| **名字要说人话** | 「计划生成 → 备课」「学员学习记录 → 本次课」「保存计划 → 执行此计划」 |

## 五、与你原始构思的差异对照

| 你的构思 | 落地结果 | 为什么改 |
|---|---|---|
| 学员 → 登记课程（私教/小班）→ 生成大纲 | 学员 → 课程包（班型 + **购买课数** + 频次 + 节奏模式）→ 大纲 | 班型不决定课次数量，买多少节才决定 |
| 生成 10 节大纲 | 按难度 × 剂量排，并明确告知「10 节只能覆盖到第几单元」 | 平均分 10 节会重演「U14 只给 2 节」的老问题 |
| 授课前生成当天详细计划 | 从大纲点「备课」自动带入并自动生成 | 少一次无决策价值的点击 |
| 右边是教案预览 + 【执行此计划】 | 顶部执行条 + 标题区底部各一个，未生成时禁用 | 教练读完教案时眼睛在底部，按钮要在视线里 |
| 点执行 → 跳到该学员的教学计划页面 + 点评按钮 | 点执行 → 「本次课」页（教案全文 + 点评按钮） | 「学员的教学计划页面」会把「这一节」和「整个大纲」混在一起；分开更清楚 |
| 也能从教学追踪进来点评 | 教学追踪每条记录有「点评」按钮，总览/今日有待点评聚合 | 漏点评是最常见的运营漏洞，要有多入口 |

## 六、接口一览（新增 8 个）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/curriculum-difficulty` | 难度与剂量表（前端解释「为什么排这么多节」） |
| POST | `/api/v1/enrollments` | 登记课程包并生成大纲（单事务） |
| GET | `/api/v1/enrollments?studentId=` | 课程包列表（含大纲，前端直接渲染） |
| GET | `/api/v1/enrollments/:id` | 课程包详情 |
| PATCH | `/api/v1/enrollments/:id` | 改节奏/状态/备注 |
| POST | `/api/v1/enrollments/:id/lessons` | **执行一节课**（幂等，单事务） |
| POST | `/api/v1/sessions/:id/review` | 课后点评 + 大纲自动顺延 |
| GET | `/api/v1/today?date=` | 今日视图（今日课 / 待点评 / 过期未上） |

`GET /api/v1/state` 现在同时下发 `enrollments`（含大纲），保证离线可用。

## 七、P7 收尾状态（已补与未做）

| 状态 | 项 | 说明 |
|---|---|---|
| **已补（本轮收尾）** | R 补强课独立教案 | 24 单元独立 R 模板（`frontend/curriculum-remedial.json`）；取消 ④ 体能段、不新增点、不加球数、作业减半；备课与本次课自动提取上节 `judgeVals` 中评为「未达标」的判据作为复测目标 |
| **已补（本轮收尾）** | 难度表驱动教案球数 + 剂量自检 | `difficulty` 随 `/state` 下发（前端离线内置兜底）；`dosageFactor` 按难度与并列新授点缩放球量（0.9–1.5，上限 40 球/人）；教案增加 `03A 剂量自检`（标注达标闸门、前置单元与拆课/补作业提醒） |
| P1 未做 | 没有课前扫码/一键上课 | 教练仍需点两下才进入本次课 |
| P1 未做 | 没有家长版一页纸 | 点评数据已经有了，只差渲染 |
| P1 未做 | 没有跟读模式（分段时间大字 + 倒计时） | 场上单手操作仍困难 |
| P2 未做 | 大纲不支持中途改单元 | 教练想跳过某单元只能改日期 |
