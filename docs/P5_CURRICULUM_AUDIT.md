# P5：教学体系与阶段晋级机制专业审查

> 审查对象：训练体系 v4.1、当前前端考核表单与判定函数、SQLite assessments 数据模型，以及 P0–P4 技术评分/动态建议实现。
> 本文是基于代码与课程文件的设计审查，不代表新标准已在真实学员样本中验证。新晋级标准在完成教练试测前不得用于线上正式判定。

## 1. 结论摘要

当前系统具备48课次课程主线、单堂技术点评分和阶段考核记录，但阶段考核尚不能可靠地证明学员达到相应比赛能力。问题不是“第16/32/48课太固定”，而是现有考核项目、评分公式、数据模型和晋级决策之间没有形成一致、可复核的能力评价体系。

建议保留第16/32/48课作为三个阶段的**建议评估窗口**，不再把它们视为必须在该课次一次性通过的硬性考试。学员可提前申请评估、在窗口期参加评估、未达标后按薄弱能力补训并重测。课程进度、评估状态和晋级资格分别记录。

## 2. 当前实现审计发现

### 2.1 评分公式与界面说明不一致（高优先级）

前端 `assessJudge()` 实际将已录入项目换算为百分制后做简单平均：`sum / cnt`。代码没有读取或应用七项独立权重；设置中的 `w` 只是单项满分，不能实现界面声称的“Σ(单项得分 × 权重)”。

此外，当前总分只除以已录入项目数，缺项不会阻止判定，可能出现少填项目仍得到高分或晋级结论的情况。

### 2.2 百分位阈值没有按百分位方式参与计算（高优先级）

设置页收集 `t1/t2/t3`（P50/P75/P90）、`line2/line3`、`w`、样本量和日期；当前判定函数只把阶段对应的 `t1/t2/t3` 当作每个指标的归一化分母，并用 `line2/line3` 判定总分。样本量、统计日期没有参与校验，P50/P75/P90 与“单项归一化基准”的语义混在一起。

相对百分位描述的是某一群体中的相对位置，不等同于绝对能力达标线。不同年龄、不同入班基础和不同训练目标的混合样本，不能直接作为统一晋级标准。

### 2.3 不同量纲被直接合成一个总分（高优先级）

现有七项为：
- 发球落点成功率（%）
- 定向击球准确率（%）
- dink 连续回合（回合数）
- 移动折返（秒）
- 步伐质量（0–5分）
- 规则与战术（分）
- 实战小分（分差）

这些指标没有统一、完整的测试协议、试次数、有效球定义、场地/喂球条件、计时规则和专项评分锚点。特别是“规则与战术分”和“实战分差”不是可互换的同一量纲。仅用一个阈值作线性比例换算，无法保证公平或信度。

### 2.4 阶段出口与实际测项不匹配（高优先级）

- 初阶出口要求发接发、NVZ dink、第三拍 drop 和规则零违规，但阶段一表单仅测试 serve、aim、foot、rule；没有独立验证第三拍 drop、dink 相持和双打场景。
- 中阶出口要求第三拍选择树、reset、长丁克旋转、flick/roll volley、lob/overhead；阶段二测项仍只有 serve、aim、foot、rule、dink、match，缺少对这些能力的直接观察。
- 高阶出口是广泛的 4.0 自评能力清单；阶段三仍复用同一组七项通用指标，无法证明高阶战术、攻防转换和对手适应能力。

### 2.5 单项门槛存在量纲错误风险（高优先级）

当前代码对 `rule` 或 `match` 使用 `t1` 作为门槛。前者为分数、后者为分差，而 `t1` 在设置界面标注为发球/初级百分位基准。将不同单位共用一个门槛可能导致不合理的补考判定。

### 2.6 补考与晋级历史缺乏结构化记录（中高优先级）

当前 `assessments` 主要存储 `stage / vals_json / total / conclusion`。没有显式记录评估协议版本、每项判定、失败原因、尝试轮次、补测关联、评估官、测试条件快照和最终审批状态。界面说明“只重测未达标项，取当次实测”，但数据模型不能完整表达该过程。

### 2.7 阶段三的“4.0”表述需要更严谨

课程文件已注明 USA Pickleball 4.0 自评清单是自评对齐，不是官方认证考试。系统输出应表述为“本课程体系的4.0能力画像/对标结果”，不能输出官方评级、认证或等同证明。

## 3. 建议的新评价架构

采用三层评价，避免把每堂课分数直接等同晋级考试：

1. **形成性评价（每堂课）**：保留现有0–5技术评分；只用于识别趋势、薄弱项和下一课教学调整。它不是阶段晋级总分。
2. **阶段能力检查（建议每4课左右）**：低成本检查最近学过的关键技能是否保留、能否在变化条件下使用。结果为通过/继续练习/需重新教学，不形成正式等级。
3. **阶段综合评估（初/中/高阶出口）**：使用明确协议和标准化场景，分别评价技术执行、战术决策、稳定性、规则与安全。结果为达标、部分达标、未达标或暂缓评估。

## 4. 阶段综合评估建议蓝图

第16/32/48课保留为默认评估窗口，但评估可在窗口前后安排；未通过不自动升级，亦不强制所有人延长整个阶段。只针对未达标能力生成补训与复测计划。

### 初阶出口：基本回合能力（约3.0能力画像）

直接观察：
- 发球合法性与可重复性；接发球深度及接发后前移意识。
- 正反手基础击球的控制能力。
- 第三拍 drop 的基本弧线、落点与可重复性。
- NVZ dink 的基本控制和连续相持。
- 两跳规则、发球规则、NVZ 规则及基本双打站位。
- 基本分腿垫步、回中与安全制动。

评估重点：能否在标准喂球和低至中等压力下建立并维持基本回合，而非只在静态定点完成动作。

### 中阶出口：攻防转换与选择能力（约3.5能力画像）

直接观察：
- 第三拍 drop / drive / drip 的情境选择与执行。
- 过渡区 block / drop / half-volley reset 的控制与连续性。
- 长丁克与NVZ短丁克的深度、旋转/节奏变化。
- 对不同来球高度选择 block / punch / flick / roll volley 的能力。
- lob、overhead 与 bounce-it 的判断和安全执行。
- 双打 stacking、沟通和轮转。
- 在受约束的半开放回合中作出正确选择，而非只完成预设动作。

### 高阶出口：比赛应用与适应能力（4.0对标能力画像）

直接观察：
- 发接发策略与第三拍、第五拍连续决策。
- NVZ相持中的节奏/旋转变化、可攻球识别、提速与反提速。
- 过渡区防守到重新进攻的完整转换。
- hands battle、counter-attack、落点选择和搭档协同。
- lob/overhead及双打战术在真实回合中的选择。
- 根据对手弱点和比分情境调整策略，并在关键分保持动作与决策质量。

ATP、Erne等高情境特殊球应作为机会识别/规则边界的专项加分观察，不建议作为所有学员晋级的单一硬门槛；除非本馆课程目标明确要求专项竞技路线。

## 5. 建议的评分与判定原则

### 5.1 不再用单一百分位线作为晋级依据

采用**标准参照（criterion-referenced）**为主：每个阶段能力项有清晰的可观察判据、测试条件、有效尝试数、成功定义和评分锚点。百分位仅用于本馆内部观察群体分布和校准，不直接决定学员是否具备能力。

### 5.2 四个评价维度

每个能力项分别记录：
- 技术执行：动作/球路是否达到该项判据。
- 决策质量：是否在正确情境选择正确技术或战术。
- 稳定性：在规定有效尝试中表现是否可重复。
- 规则与安全：是否遵守规则、是否能安全移动和控制动作。

建议用0–4级专项锚点（未观察/无法完成、需持续提示、部分达到、标准条件稳定达到、变化/对抗条件下稳定运用）。现有0–5课堂量表继续服务形成性评价，阶段评估可使用独立rubric，避免混用。

### 5.3 晋级采用“关键项门槛 + 综合画像”，而非总分补偿

- 规则与安全为硬门槛，不能被发球或击球高分抵消。
- 每阶段列出关键能力项；关键项未达标时，结论为“暂不晋级/部分达标”，并输出具体补训内容。
- 非关键扩展项允许记录为发展目标，不应因为罕见技术（例如ATP/Erne）单项失败就否定整体比赛能力。
- 综合分可用于描述优势和短板，但不允许以总分掩盖关键技术、决策或安全短板。
- 所有必测项均需完成；缺测显示“未评估”，不能当作0分，也不能被排除后重新平均。

### 5.4 可靠性与重测

- 采用统一场地、球、喂球/对抗条件、试次数、计分方法和休息安排。
- 保存每项原始尝试与结果，不只存最终均分。
- 重测只重测未达标项时，必须关联原评估记录并保留新旧结果；不能覆盖历史。
- 对接近门槛或观察不一致的项目，允许第二次观察/录像复核。
- 青少年、常青和有伤病备注者使用适龄/安全协议；涉及医疗判断的情形不进行自动测试结论。

## 6. 数据与产品改造建议

建议新增版本化的评估定义与结果实体，而不是继续把所有内容塞进 `assessments.vals_json`：

- `assessment_protocols`：阶段、版本、适用年龄/训练路线、测试条件、发布状态。
- `assessment_criteria`：协议中的能力项、是否关键项、维度、rubric、顺序。
- `assessment_attempts`：学员、协议快照、评估日期、关联课次/授课记录、评估人、状态、重测关联、总览结论。
- `assessment_criterion_results`：每项原始尝试、成功数、得分、达标状态、教练观察和证据引用。

旧 `assessments` 数据只读保留，标记为legacy；新旧记录并行迁移，完成历史映射验证后再考虑退役旧结构。所有评估结论必须绑定协议版本快照，避免规则更新后历史成绩被重新解释。

## 7. P5实施顺序

1. P5-A：修正当前考核的安全性问题——必测项缺失不得计算晋级；删除“权重”误导或真正实现有定义的权重；不同量纲不再共用门槛；对阈值与输入做范围校验。
2. P5-B：新增版本化评估协议/能力项/单项结果数据结构，旧记录只读兼容。
3. P5-C：配置初阶/中阶/高阶能力矩阵与可执行测试协议；由教练在真实班级试测后发布。
4. P5-D：考核结果驱动个性化补训、复测和阶段路线调整；保留教练最终确认。
5. P5-E：报告呈现能力画像、关键项达标情况、证据与后续训练建议，不再只显示一个总分和“晋级/补考”。

## 8. P5-A 已实施的安全修正（2026-11-18）

- 前端不再根据旧七项指标、旧百分位阈值和旧综合分自动输出「晋级 / 补考」；新录入的旧指标记录标记为 `legacy_pending_review`，总分保持空值，等待教练复核。
- 保存时强制检查当前阶段必测字段是否完整；缺项提示具体字段，不把缺测当作0，也不允许用已填项目重新平均。
- 对发球/定向准确率（0–100）、步伐质量/规则分（0–5）、折返时间（>0）和dink回合数（非负）做基础范围校验。实战分差保留正负值，但仅记录，不参与晋级计算。
- 考核界面与阈值设置界面已明确标记旧阈值仅供追溯，不参与当前晋级判定。
- 旧历史考核记录不改写、不删除；新评估协议发布前，不从旧记录自动推导学员晋级状态。

注意：P5-A 是风险隔离，不是新晋级算法。新版协议和阶段专项测试尚未完成；本次前端改动需由CI和教练验收后再进入后续阶段。

## 9. 当前不应自动做的事情

- 不应把P50/P75/P90直接当作固定绝对能力线。
- 不应把所有技术评分0–5简单平均后自动晋级。
- 不应因第16/32/48课已完成就自动升级阶段。
- 不应把USA Pickleball自评清单结果说成官方认证。
- 不应把ATP/Erne等低频特殊球设为所有学员的必过项。
- 不应在没有教练试测与样本校准前，擅自发布新的数值型晋级线。



## 10. P5-B：版本化评估协议与单项证据结构（已建立，仍为试测稿）

新增迁移 `004_assessment_protocols.sql`，建立四类实体：
- `assessment_protocols`：阶段、协议代码/版本、适用路线/年龄、发布状态、测试条件和校准状态。
- `assessment_criteria`：能力项、四维评价分类、必测/关键门槛标记、评分rubric、测试任务和待校准规则。
- `assessment_attempts`：学员、协议版本快照、日期、关联课次/授课记录、评估人、状态、复测关联。
- `assessment_criterion_results`：单项分数（0–4）、达标状态、原始尝试、观察与证据引用。

迁移写入初/中/高阶三份 **draft** 协议蓝图，覆盖对应阶段出口能力。所有试次数、成功定义和通过线均明确标记待教练试测，不写入未经验证的数值门槛。初阶包含第三拍drop与NVZ dink；中阶包含第三拍选择、过渡区reset、截击选择和双打轮转；高阶包含连续决策、NVZ节奏、过渡区攻防和双打适应。

新增API：
- `GET /api/v1/assessment-protocols?stage=1&status=draft`
- `GET /api/v1/assessment-protocols/:id`
- `POST /api/v1/assessment-attempts`
- `GET /api/v1/assessment-attempts/:id`
- `PUT /api/v1/assessment-attempts/:id/results`
- `GET /api/v1/students/:id/assessment-attempts`

新评估创建时固化协议快照；复测必须关联同一学员、同一协议版本。旧 `assessments` 表及历史数据保持不动。当前协议全部为草案，API只允许采集试测资料，不提供发布、晋级或自动结论能力；阶段结果的教练复核与正式发布留待后续阶段。
