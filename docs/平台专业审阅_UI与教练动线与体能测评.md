# 匹克球教学管理平台 · 专业性与易用性审阅

> 审阅对象：`jervis829/Pickleball`（前端 `frontend/index.html` 单文件 + `frontend/api.js` + Node 零依赖后端 + SQLite）。
> 审阅方式：通读全部代码（前端 1,700+ 行、后端 12 个模块、6 个迁移、31 项集成测试），并实际启动服务跑通完整流程。
> 结论先行：**这套平台的"教学专业度"已经超过绝大多数商业教学系统**（48 课次实数化教案、8 族技术覆盖自检、三层评估、明确拒绝自动晋级）。真正拖后腿的不是内容，而是**信息架构、教练现场操作路径、以及"身体"这一维度的数据化**。本文按你给的三个问题逐条回答，最后给出改造优先级。

## 一、UI / UA 合理性评估

### 1.1 做得好的地方（建议保留，不要为了"改版"而改）

| 项 | 评价 |
|---|---|
| 视觉系统 | 单一强调色（酸橙）+ 极深底色 + 等宽数字，信息密度高但不吵；对比度、焦点态、`prefers-reduced-motion` 都照顾到了 |
| 导航 | 6 项一屏放下，编号 1-6 可直接键盘切换 —— 教练一只手也能操作 |
| 教案输出 | 三种视图（详细教案 / 结构表 / 打印稿）+ 一键复制 + 打印样式，这是真正"能带到球场"的设计 |
| 状态诚实 | 离线时明确显示「离线 · 仅本机」「未登录 · 离线模式」，从不假装已同步；未校准阈值显示「无法判定」而不编造数字 |
| 空状态 | 每个空页面都给下一步动作（新增学员 / 载入示例），不是干巴巴一句"暂无数据" |
| 打印 | `@media print` 把侧边栏、表单、Tweaks 全部隐藏，只留教案正文 |
| 数据可追溯 | KPI 每个数字下面直接写公式（`出勤记录 ÷ 授课记录 × 100`），不展示无来源数字 |

### 1.2 结构性问题

| # | 问题 | 严重度 | 具体表现 | 建议 |
|---|---|---|---|---|
| A1 | **信息架构按"功能"分，不按"教练的一天"分** | 高 | 教练的真实动线是：今天谁来 → 他们练到第几课 → 今天带什么 → 课后记什么 → 谁该考核/续费。现在被拆成 6 个平级页面，每次上课要在 3 个页面之间跳 | 加一个「**今日**」首页：按今天排课列出学员卡（姓名 / 第几课 / 上次薄弱项 / 伤病标记 / 剩余课次），每张卡直接给「生成教案」「记记录」两个按钮 |
| A2 | **「考核与晋级」是一堵墙** | 高 | 单个 `#view-assess` 里塞了：旧七项录入（已停用）、晋级判定、考核记录、新版阶段协议 + 教练复核 + 补训计划 + 限定复测。老教练找不到入口，新教练看不懂为什么有两套 | 拆成两个页面：「**阶段评估**」（日常用，按测试卡逐项打分）与「**评估设置**」（协议、校准、历史，低频）。旧七项直接折叠标记「历史记录（只读）」 |
| A3 | **「体系与设置」混了三种东西** | 中 | 生成依据 / 默认假设 / 训练参数（63 项）/ 阈值校准 / 数据服务账号 / 数据管理，全在一页 | 分三块：**训练参数**（高频，教练会改）｜**机构设置**（低频）｜**账号与数据**（极低频） |
| A4 | **没有"学员视角"** | 中 | 全站都是教练视角。家长问"我孩子进步了吗"，教练只能口头说或导 JSON | 学员详情页已有「技术成长」与「体能报告」，加一个「打印/发送给家长的一页纸」（雷达图 + 3 条进步 + 下阶段重点） |
| A5 | **移动端只做到"能用"** | 中 | 侧边栏在 900px 下变成横向滚动条；`plan-layout` 塌成单列，但教案正文很长，场上单手翻找很痛苦 | 教案页加"当前段"高亮 + 上一段/下一段按钮（现场跟读用）；表格在窄屏改成卡片 |

### 1.3 细节问题（影响手感，不影响理解）

| # | 问题 | 建议 |
|---|---|---|
| A6 | 快捷键 1-7 有，但没有任何地方提示 | 侧边栏已有 `1`-`7` 角标，够了；补一个 `?` 帮助浮层即可 |
| A7 | 「Tweaks」浮层是开发期产物，却在生产界面 | 保留（教练确实喜欢切密度），但改成齿轮图标，文字改「显示设置」 |
| A8 | 教案页左侧表单固定宽 352px，教案正文很长时左侧留白 | 生成后自动折叠左侧表单 |
| A9 | 图表用手写 SVG（雷达图）——好，但缺少"图上直接标注数字"的对比色 | 已经做了（每个轴端点有数值 + 等级色），保留 |
| A10 | Toast 只有 2.2 s，且右上角无历史 | 关键操作（保存计划、生成报告）改成页内确认条，不依赖 toast |
| A11 | 表格数字未统一右对齐/等宽 | `td.num` 已有等宽，但部分表格漏用 |
| A12 | 无暗色/亮色之外的"户外高对比"模式 | 室外球场强光下暗色界面几乎不可读，加一个「户外模式」（白底黑字 + 大字号） |

### 1.4 可访问性（a11y）

- 已有：`focus-visible` 描边、`aria-current` 导航态、`aria-pressed` 分段控件、`prefers-reduced-motion`、`role="img"` 雷达图。
- 缺：表单 `label` 未全部用 `for/id` 关联（靠视觉排布）；模态框没有焦点陷阱与 `aria-modal`；错误提示未用 `aria-live`。
- 建议：模态框加 `role="dialog" aria-modal="true"` + Esc 关闭（已有）+ 打开时聚焦第一个输入框；错误统一 `aria-live="polite"`。

## 二、教练使用时"不趁手"的地方

按真实上课动线排序，每条都给出改法。

### 2.1 课前（找学员、定课次）

| # | 痛点 | 现场会发生什么 | 改法 |
|---|---|---|---|
| B1 | 生成计划要手动勾学员 + 手动选课次，虽然有"推荐课次"，但 **8 人团课要勾 8 次** | 教练在开课前 2 分钟手忙脚乱 | 支持**班次/小组**：把固定的 8 人存成一个「周三晚 7 点班」，一次选中；课次自动取该班"最小已耗课次 + 1" |
| B2 | **没有"今天"视图**，要先去学员档案看谁该上第几课 | 每次都要重新算 | 见 A1 |
| B3 | 出勤是课后补录的，课前不知道谁请假 | 备课内容与实到人数不符 | 加"课前点名"（30 秒），点名后生成教案时自动按实到人数调整分层任务 |
| B4 | 伤病标记只在学员详情页有一行红字；生成教案时才知道 | 可能已经把高冲击动作排进去了 | 学员列表直接显示 `需评估` chip（已有）；生成前把"本节涉及高风险动作 + 相关学员"提前列在表单底部 |

### 2.2 课中（照着教案带）

| # | 痛点 | 现场会发生什么 | 改法 |
|---|---|---|---|
| B5 | 教案很长（详细视图 20+ 动作块），**手上拿手机翻很难** | 教练干脆不看了，凭记忆带 | ①「**一页速查卡**」视图：6 段 × 3 行（做什么 / 多少 / 判据），A4 一页；②「**跟读模式**」：全屏大字，每段一屏，左右滑动翻段，带计时 |
| B6 | 段内时间只有区间（`10-13 min`），**没有倒计时** | 经常压不住时间，最后收尾被砍 | 跟读模式里加段落倒计时（可暂停），到点震动/提示 |
| B7 | 判据是文字，**现场没法快速勾** | 课后凭记忆补录，数据失真 | 「**快速记分**」：当前学员 × 3 个要点 × 三档（达标/部分/未达），大按钮，点一下就存 |
| B8 | RPE 课后才问，**课中不知道学员强度够不够** | 常青可能已经超了 | 跟读模式里每段末尾一句"口头确认"（说话测试：能不能说完整句子），教练点一下记 |
| B9 | 场地动线是文字描述 | 需要移步时容易乱 | 动线改成一张小示意图（球场俯视 + 1 个功能区 + 集合点），比文字快 |

### 2.3 课后（记录、反馈、家长沟通）

| # | 痛点 | 现场会发生什么 | 改法 |
|---|---|---|---|
| B10 | 要分两步：先"保存计划"，再"补录授课记录"，再"技术评分"。**三处录入同一节课** | 教练只做第一步，后面数据永远缺 | 合并成一次「**课后 60 秒**」：出勤 → 3 个要点打勾 → RPE → 一句话反馈 →（可选）技术评分。一次提交写三个表 |
| B11 | 技术评分要打开模态框、逐项下拉 0-5、还要填尝试/成功次数 | 8 人 × 4 项 = 32 次下拉，没人会做 | 改成"滑动/点选 0-5 圆点"，尝试/成功改可选；默认带出上次分数供参考 |
| B12 | 阶段评估要"创建 attempt → 逐项录分 → 逐项教练复核 → 生成补训 → 建复测"，**6 步** | 只有最认真的教练会走完 | 加「**一键评估**」：选协议 → 一屏打完所有项 → 一次教练确认 → 自动出结论与补训建议（复核仍保留，但默认"确认"） |
| B13 | 家长沟通没有产出物 | 续费谈判缺弹药 | 见 A4「一页纸家长报告」 |
| B14 | 缺"下次课重点"的自动衔接（其实教案里有 nextLabel，但只有教练看得到） | 学员回家就忘 | 课后在报告页显示"下节课预告"，可直接复制发微信 |

### 2.4 管理者（店长/老板）

| # | 痛点 | 改法 |
|---|---|---|
| B15 | KPI 有 10 个，但**没有趋势**（只有当天值） | 加 8 周趋势线（在训人数、出勤率、续费预警） |
| B16 | 没有"教练工作量"视图 | 按教练统计课时、学员数、评估完成率 |
| B17 | 备份要手动导出 | 已有自动部署脚本与 Docker，但数据备份可加"每周自动导出一份到 `data/backups/`" |
| B18 | 权限只有 admin/coach/viewer 且没有界面 | 加一个账号管理页（新增教练账号、只读账号给前台） |

### 2.5 一句话总结"不趁手"的根因

> **平台是"教案生成器 + 数据库"，不是"教练的上课工具"。**
> 它把"备课"做得非常专业（这是最难的），但把"上课"和"课后 60 秒"做成了表单。教练在场上没有第三只手，所以任何需要"打开页面 → 找到位置 → 填 3 个字段"的操作，最终都会被跳过 —— 数据一断，专业性就归零。

改造顺序建议：**跟读模式（B5/B6/B7）→ 课后 60 秒（B10/B11）→ 今日视图（A1/B1/B3）→ 阶段评估一键化（B12）**。

## 三、入班身体素质评估 → 图文报告 → 驱动训练计划

**结论：这是对的方向，而且已经落地实现。** 但要先说清"为什么值得做"和"必须避免什么"。

### 3.1 为什么值得做（三个真实收益）

1. **把主观分变成可核对的数据。** 原来"入班体能 3 分"没有任何依据；现在 9 项实测 → 9 维指数 → 综合指数 → 0-5。同样的 3 分，报告能告诉你"是下肢还行、有氧偏弱、灵敏最差"。
2. **让教案 ④ 段有的放矢。** 原来 ④ 段对所有 3 分学员都排"力量 3×12 + 灵敏 3×20 s"；现在会写"该学员灵敏 32（待建立）→ ④ 段先加侧滑与交叉步、对抗段设『接完即上』计分"。
3. **给续费和家长沟通一个客观锚点。** 8 周复测，雷达图从"凹三个角"变成"凹一个角"，这是最有说服力的进步证明。

### 3.2 已经实现的内容（可直接使用）

| 项 | 实现 |
|---|---|
| 测试项 | 9 项：反应尺、坐位体前屈、单腿站立、对墙击球 30 s、立定跳远、5-10-5 折返、俯卧撑 30 s、平板支撑、3 分钟台阶后 1 分钟心率 |
| 维度 | 反应 / 灵敏 / 爆发 / 上肢力量耐力 / 核心 / 有氧 / 柔韧 / 平衡 / 手眼协调（9 维加权，权重和为 1） |
| 适龄变体 | 常青：3 m 折返、墙面俯卧撑、屈膝平板、15 cm 台阶、坐站起立替代立定跳远；少儿：跪姿俯卧撑、低台阶 |
| 报告 | 九维雷达（SVG，可打印）+ 维度条形图 + 强项/补强 + 计划适配建议 + 逐项实测表 + 与教练自评的交叉校验 |
| 与计划的关系 | 教案自动追加「04B 体能测评 → 本课 ④ 段适配」，并影响 RPE 上限与负荷保护 |
| 安全口径 | 未测/中止/禁忌**不当作 0 分**；≥6 项且 ≥4 维度才能出正式报告；完成后锁定，复测另建；附教练确认后回写档案 |
| 教练操作 | 左侧导航「体能测评」（快捷键 7），录入时**即时显示指数**，一次测评约 28 分钟 |

### 3.3 三个必须避免的坑（我已在实现里规避，但你要知道）

| 坑 | 说明 | 我的处理 |
|---|---|---|
| **把推定分档说成"标准"** | 9 项的 5 档锚点目前来自通用体能测试常见区间，**没有本馆样本验证**。若对外宣称"国家标准"，一旦被同行或家长追问就崩 | 报告固定展示「参考分档（推定值），不是官方常模」；文档写明"≥30 人样本后替换为本馆分位" |
| **把年龄让步做成一刀切折扣** | 常见错误：常青所有项目 ×0.7。结果常青的柔韧（本就好于成人）被压低，爆发（确实下降）被高估 | 改为**分维度让步，且在指数空间**：常青有氧/爆发放宽，少儿柔韧执行**更严**标准 |
| **用体能分决定晋级** | 体能好 ≠ 技术达标；技术好也不能掩盖体能短板 | 体能测评**只影响 ④ 段与 RPE 上限**，不参与任何晋级判定；与阶段能力评估完全独立、互不覆盖 |

### 3.4 建议再补的三件事（下一步）

1. **本馆校准（最重要）**：累计 30 名同学段学员后，把 5 档锚点换成实测分位（P25/P50/P75/P90），记录样本量与日期；**替换前后报告不可直接比较**。
2. **信度检验**：两位教练独立观察同一批学员（尤其对墙击球、折返的判定），比较评分一致性；不一致的项要么改判据，要么改测试方法。
3. **报告对外版**：给家长的一页纸（雷达图 + 3 条进步 + 下阶段重点），去掉内部指数与"待建立/偏弱"等刺眼词，改成"当前重点 / 已具备"。

### 3.5 一张图说清模块间的关系

```

                    └─→ 无红旗
                          ↓
                  9 项体能实测（28 分钟）
                          ↓
                  0-100 指数 × 9 维 → 图文报告
                          ↓

            回写入班体能 0-5    训练计划 ④ 段重点 / RPE 上限

```

## 四、改造优先级（按"教练真正会用"排序）

| 优先级 | 改动 | 理由 | 预估工作量 |
|---|---|---|---|
| P0 | 跟读模式（全屏分段时间大字 + 倒计时 + 快速判据打勾） | 唯一能让教练"在场上真的用起来"的功能 | 中 |
| P0 | 课后 60 秒（合并保存计划 / 授课记录 / 技术评分） | 数据断点在这里，不修则所有统计失真 | 中 |
| P1 | 今日视图 + 班次/小组 | 解决课前 2 分钟的手忙脚乱 | 中 |
| P1 | 一页速查卡视图 + 打印优化 | 直接替代现在"翻 3 页" | 小 |
| P2 | 阶段评估一键化（默认确认，保留逐项复核） | 让评估真正发生 | 中 |
| P2 | 家长一页纸（含体能雷达 + 技术成长） | 续费与口碑 | 小 |
| P3 | 账号管理页 / 教练工作量 / KPI 趋势 / 户外模式 | 管理与体验完善 | 中 |

## 五、一句话结论

**内容层面：这套体系与平台已经达到"可以直接开馆授课"的专业度，不需要重写。**
**产品层面：它现在更像"给教练备课的编辑器"，下一步要做成"教练在场上的工具"—— 把跟读、快速记录、今日视图这三件事做掉，「不趁手」的问题会消失八成。**
**数据层面：入班 9 项体能实测已经落地，它把"身体"这一维从主观印象变成了可对比的数据，是这套平台从"教案库"走向"教学系统"的关键一步。**
